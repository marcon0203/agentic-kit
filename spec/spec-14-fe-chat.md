# spec-14 Chat 运行详情页（核心）

> 对应任务 `task_implement.json#14` | 依赖：#13 fe_foundation、#12 event_stream
> 关联：PRD「六、线框图 - 3. 运行详情页」、架构文档「6.7 事件流接口」

## 目标

把 Bundle 的多 Agent 协作过程呈现为一场**对话**：用户描述需求，各角色 Agent 的产出以气泡形式流式出现，human gate 审批作为内联卡片插在对话中间，执行图退居右侧辅助栏。

选择 Chat 而非纯仪表盘的理由：多 Agent 协作本质是团队讨论，对话流天然表达"谁在什么时候说了什么"；用户不必先学会看执行图才能上手。

## 事件驱动映射

| 事件 | UI 行为 |
|---|---|
| `bundle.started` | 初始化对话流 |
| `node.started` | 新建该 Agent 的气泡，状态「运行中」 |
| `node.thinking` | 气泡内打字机效果追加文本 |
| `node.tool_call.started/finished` | 气泡内渲染一行「正在调用 xxx 工具」状态条 |
| `node.finished` | 气泡定稿，显示「查看完整产出」链接 |
| `node.failed` | 气泡标红，展示错误信息（黑盒运行时已脱敏） |
| `human_gate.waiting` | 在对话流末尾插入审批卡片 |
| `human_gate.resolved` | 卡片折叠为「已通过/已驳回」状态条 |
| `shared_state.updated` | 更新右侧共享状态面板 |
| `bundle.finished/failed` | 流关闭，指示器变「已结束」 |

## 关键实现

### 1. 事件流消费（POC 已验证）

```ts
const res = await fetch(`${BASE}/api/v1/runs/${runId}/stream`, { signal: controller.signal });
const reader = res.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done || cancelled) break;
  buffer += decoder.decode(value, { stream: true });
  const lines = buffer.split("\n");
  buffer = lines.pop() ?? "";   // 最后一段可能是不完整的行，留到下次拼接
  // 逐行 JSON.parse 并追加
}
```

### 2. StrictMode 双挂载竞态（POC 阶段真实踩过的坑）

React 开发模式下 effect 挂载两次，第一次的 fetch 被 abort 后，它的 `finally` 依然会执行并把 `streaming` 设为 `false`，覆盖掉第二个实例刚设的 `true`——表现为"页面一打开就显示已结束，但数据在正常接收"。

必须用 `cancelled` 闭包变量保护：

```ts
useEffect(() => {
  const controller = new AbortController();
  let cancelled = false;
  // ...
  finally {
    if (!cancelled) setStreaming(false);   // 关键判断
  }
  return () => { cancelled = true; controller.abort(); };
}, [runId]);
```

**凡是 effect 里有异步操作且会更新 state，都要做这个保护。**

### 3. 并行 Agent 的并排布局

同时处于「运行中」的多个节点，其气泡以横向并排呈现（宽度均分），直观表达"同时在干活"。判断依据：多个 `node.started` 之间没有夹着对应的 `node.finished`。

### 4. 黑盒模式降级

`run.via_listing_id` 非空且当前用户非作者时：

- 执行图只渲染占位节点（不显示真实节点名与拓扑）
- 共享状态面板只展示 `listing.display_meta.io_description.outputs` 中声明的字段
- 时间线不显示 `node.thinking` 类事件（后端已过滤，前端做二次防御）

### 5. human gate 权限

审批卡片对所有查看者可见，但**操作按钮仅对具备审批角色的用户渲染**；其他用户看到「等待他人审批」。前端隐藏按钮只是体验，真正的拦截在后端（50004）。

## UI/UX设计

> 遵循 `design-system.md`。本页是产品核心界面，用到三个平台自定义组件：`ds-agent-bubble`、`ds-graph-node`、`ds-gate-card`。

**改为浅色**（上游深色配色作废）：页面底 `surface-page`，对话区与右侧栏均为 `surface` 卡片 + 1px `border` + `rounded.lg`。

### 关键交互流程

**流式产出**：`node.thinking` 逐字追加到气泡正文，末尾显示闪烁光标；`node.finished` 后光标消失、气泡左边框由 `primary` 转 `success`、底部出现「查看完整产出」链接。

**工具调用**：`node.tool_call.started` 在气泡内插入一行状态条（`surface-muted` 底 + `rounded.xs` + 图标 + 「正在调用 xxx」）；`finished` 后状态条转为完成态并可折叠。

**并行 Agent**：多个节点同时 running 时，气泡横向并排等分宽度，直观表达"同时在干活"。判断依据是多个 `node.started` 之间没夹着对应的 `node.finished`。

**审批**：`human_gate.waiting` 在对话流**末尾内联插入** `ds-gate-card`（不是弹窗——审批需要参考上文做判断，弹窗会遮挡上下文，也与"对话"的产品隐喻冲突）。处理后折叠为单行状态条，保留在对话流中作为历史记录。

**自动滚动**：新消息到达时滚动到底部；但用户主动向上滚动后**暂停自动滚动**，改为在右下角显示「有新消息 ↓」浮标，避免打断用户回看。

### 各状态呈现

| 状态 | 呈现 |
|---|---|
| Loading（首次加载） | 对话区显示 3 条骨架气泡，中性灰微光；右侧栏骨架 |
| Empty（刚创建尚无事件） | 对话区显示用户的初始需求气泡 + 「正在启动…」状态条，不显示空态面板（运行必然会产生内容） |
| Error（流中断） | 顶部内联错误条 + 「重新连接」按钮，已收到的消息保留不清空 |
| Error（运行失败） | 失败节点气泡转 `error` 态；对话流末尾插入失败说明条 |
| Success（完成） | 流状态指示器转「已结束」，末尾插入完成条 + 耗时统计 |
| 黑盒运行 | Agent 名后加「黑盒」chip；执行图渲染为占位节点；共享状态仅显示 `io_description` 声明字段；不显示 thinking 过程 |

### 响应式

| 断点 | 行为 |
|---|---|
| >1260px | 左右分栏 1.08fr/.92fr |
| 901–1260px | 保持分栏，右侧栏收窄；并排 Agent 气泡改为纵向堆叠 |
| ≤900px | 右侧栏移至对话区下方，改为可折叠面板 |
| ≤720px | 全单列，输入区固定底部，操作按钮通栏 |

### 无障碍要点

- **流式内容播报**：气泡逐字追加期间设 `aria-busy="true"`，`node.finished` 后置 `false` 并用 `aria-live="polite"` 播报完整产出——**不要在追加过程中用 aria-live**，否则每追加一个字就重播一次
- **执行图键盘可达**：每个节点可 Tab 聚焦、Enter 展开详情；「时间线」tab 作为执行图的等价纯文本替代路径
- 审批按钮命中区 ≥40×40px，`ds-gate-card` 出现时用 `aria-live="assertive"` 播报（这是需要用户行动的内容）

### 补充：停止运行（P0-15）

运行头部右侧提供「停止运行」次按钮（`button-secondary`，仅 running 状态可见）。点击弹出确认弹窗：

- 标题：「确定停止这次运行？」
- 正文说明：已生成的产出会保留；**已消耗的 Token 无法退回**（当前已消耗 X tokens ≈ $Y）
- footer：「继续运行」次按钮 + 「停止」danger 按钮

停止后对话流末尾插入状态条「运行已被手动停止」，执行图未完成节点转灰。

补充验收项：
- [ ] 「停止运行」仅在 running 状态可见
- [ ] 确认弹窗明确告知已消耗 Token 不退回，并显示当前消耗量
- [ ] 停止后 5 秒内界面反映为已停止状态
- [ ] 停止后已产生的产出与事件完整保留，可正常查看
