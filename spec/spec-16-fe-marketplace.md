# spec-16-fe-marketplace 应用广场前端

> 对应任务 `task_implement.json#16` | 依赖：#13 fe_foundation、#8 marketplace
> 关联：docs/架构设计文档_AI-Agent平台_V1.md、docs/PRD_AI-Agent平台_AgentBundle编排与运行_V1.md、api/openapi.yaml

## 目标

应用广场的浏览、订阅、发布与订阅管理界面。

## 页面清单

| 页面 | 要点 |
|---|---|
| 广场浏览 | 卡片列表、类型筛选、搜索、分页；已订阅卡片显示「进入使用」 |
| 资源详情 | 简介/使用说明/输入输出/**执行约束**/版本历史；黑盒提示 |
| 我的发布 | 发布表单、版本管理、订阅数与运行次数、停止分发 |
| 我的订阅 | 列表、新版本提示、显式升级、退订 |

线框图见 PRD 六.4。

## 黑盒呈现规则

详情页**必须展示**执行约束（最大工具调用数、超时、预计 Token 范围）——这是黑盒规则的必要例外，否则订阅者无法预估成本。

详情页**不得展示** persona、编排图、内部节点名。版本历史只显示作者手写的 changelog，不显示 diff。

## 升级流程

订阅列表中 `latest_version !== subscribed_version` 时显示「有新版本」徽标 + 作者的更新说明，用户点击后**显式确认**才升级——不自动生效。

## 验收清单

- [ ] 广场列表支持类型筛选与关键词搜索
- [ ] 详情页展示执行约束，不展示任何内部定义
- [ ] 订阅后卡片状态变为「已订阅/进入使用」
- [ ] 发布表单在依赖校验失败时展示具体是哪个资源的问题
- [ ] 有新版本时显示提示与 changelog，升级为显式操作
- [ ] 退订后资源从我的列表消失，历史运行记录仍可查

## UI/UX设计

> 遵循 `design-system.md`。用到平台自定义组件 `ds-listing-card`。本页最需要警惕的是**黑盒信息边界**——视觉设计要主动帮工程师避免泄露。

### 页面布局

**广场浏览**：内容型页面，用衬线标题 `headline-lg` 建立"编辑过的知识"观感 → 工具栏（搜索 `input` + 类型 `ds-tab`）→ `ds-listing-card` 栅格（3→2→1 列，间隙 `gutter` 24px）→ 分页。

**资源详情**：`1.08fr / .92fr` 非对称分栏——左侧简介/使用说明/输入输出，右侧订阅操作区（sticky）+ 执行约束 + 版本历史。

```
┌────────────────────────────────────┬──────────────────┐
│ 全栈应用生成器  《Bundle》《黑盒》      │  ( 订阅 v2.0 )    │ ← 主按钮
│ @李四 · v2.0 · 56 人订阅 · 运行 1204 次│  [ 举报 ]         │
├────────────────────────────────────┤                  │
│ 简介 / 怎么用 / 输入输出              │  执行约束 ⚠必须展示│
│                                      │  最大工具调用 40   │
│                                      │  超时 900s        │
│                                      │  预计 30k~60k tok │
│                                      ├──────────────────┤
│                                      │  版本历史          │
│                                      │  v2.0 更新说明...  │
└────────────────────────────────────┴──────────────────┘
```

### 黑盒边界的视觉约束

**必须展示**：执行约束（最大工具调用数、超时、预计 Token 范围）——这是黑盒规则的**必要例外**，不展示订阅者无法预估成本。视觉上单独成块并加说明「用于预估运行成本」。

**绝不展示**：persona 提示词、编排图、内部节点名。版本历史**只渲染作者手写的 changelog 文本**，不提供任何 diff 视图入口——diff 会泄露黑盒内容。

页面显著位置放「黑盒」chip + 底部说明条「该资源为黑盒发布，内部编排结构与提示词不公开」，让订阅者对边界有预期，而不是以为是页面加载失败。

### 关键交互流程

**订阅**：点击「订阅 v2.0」→ 确认弹窗（说明将绑定到 v2.0，作者后续更新不自动生效）→ 成功后按钮变「进入使用」次按钮 + 出现「已订阅」chip，Toast 提示。

**升级**：订阅列表中 `latest_version !== subscribed_version` 时，卡片右上角显示「有新版本」`warning` 色 chip → 点击展开作者的 changelog → 「升级到 v2.1」主按钮 → **显式确认弹窗**后才升级。**绝不自动升级**。

**发布**：表单填写 → 提交触发依赖完整性校验 → 失败时错误面板列出**具体是哪个字段的哪个资源**（映射后端 `details[]`），并提供「去发布该资源」的跳转链接。

### 各状态呈现

| 状态 | 呈现 |
|---|---|
| Loading | 卡片骨架 6 个，中性灰 |
| Empty（广场无内容） | 虚线面板 + 「广场还没有内容」+ 「发布我的第一个资源」主按钮 |
| Empty（搜索无结果） | 虚线面板 + 「没有找到相关资源」+ 「清除筛选」次按钮 |
| Empty（我的订阅为空） | 虚线面板 + 「还没有订阅任何资源」+ 「去广场看看」主按钮 |
| Error | 内联错误面板 + 重试 |
| Success（订阅成功） | Toast + 卡片状态即时更新，无需刷新 |
| 已下架资源 | 卡片置灰 + 「已下架」chip，操作按钮禁用并说明原因 |

### 响应式

卡片栅格 3→2→1 列随断点降级；详情页 ≤900px 时右侧订阅区移至标题下方，保持「订阅」按钮在首屏可见。

## UI验收标准

- [ ] 详情页**展示**执行约束（工具调用数/超时/预计 Token），并注明用于预估成本
- [ ] 详情页**不展示** persona、编排图、内部节点名
- [ ] 版本历史只显示作者手写 changelog，**无任何 diff 视图入口**
- [ ] 「黑盒」chip 与底部说明条同时存在，让用户理解信息边界而非以为加载失败
- [ ] 订阅前有确认弹窗，明确说明绑定到具体版本
- [ ] 订阅成功后卡片即时变为「进入使用」+「已订阅」chip，无需手动刷新
- [ ] 有新版本时显示 `warning` chip + changelog，升级需显式确认，**不自动生效**
- [ ] 发布依赖校验失败时，错误面板指出具体字段和具体资源名
- [ ] 三种空态（广场空/搜索无果/订阅空）文案与操作按钮各不相同
- [ ] 已下架资源卡片置灰且操作禁用，并说明原因（不只是变灰）
- [ ] 卡片 hover 仅上移 4px + 阴影提升，**未整体缩放**
- [ ] 卡片栅格随断点 3→2→1 降级
- [ ] 卡片标题用衬线 `title-card`，作者等元信息用 `caption`
- [ ] 每张卡片只有一个主按钮

### 补充：发布失败的依赖引导

递归依赖校验失败时，**不能只甩一条错误信息**——作者可能有多个未发布的依赖，逐个试错体验很差。错误面板设计：

```
┌────────────────────────────────────────────────┐
│ ⚠ 存在 2 个未发布的依赖，无法发布                 │
│                                                  │
│ ① mcp/internal-search @1.0                      │
│    路径 web-app-builder → architect@1.0 → 该资源  │
│                              [ 去发布 ]          │
│ ② product_manager @1.2                          │
│    路径 web-app-builder → 该 Agent               │
│                              [ 去发布 ]          │
│                                                  │
│ 全部发布后再回来重试            ( 重新校验 )      │
└────────────────────────────────────────────────┘
```

- 每条列出**完整依赖路径**，让作者理解为什么需要它
- 每条配「去发布」按钮，跳转到该资源的发布表单（**新标签页打开**，不丢失当前填写的内容）
- 底部「重新校验」按钮，处理完依赖后原地重试，不用重填表单

补充验收项：
- [ ] 多个未发布依赖时全部列出，不是只显示第一个
- [ ] 每条显示完整依赖路径（如 `A → B → C`），不只是资源名
- [ ] 每条提供「去发布」入口，新标签页打开且不丢失当前表单内容
- [ ] 提供「重新校验」按钮，可原地重试
- [ ] 停止分发被拒绝时（70007），列出具体哪些资源在依赖它
